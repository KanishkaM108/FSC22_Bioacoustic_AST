# FSC22 clean unseen-recording experiment

This package replaces the augmentation-before-row-split experiment with a
source-disjoint protocol suitable for a generalisation claim.

## What is protected

- The grouping key is derived from `Source File Name`. For example, segments
  `17548_A.wav` and `17548_B.wav` belong to the same FreeSound source group.
- A source group can appear in exactly one of train, validation, or test.
- Original and pitch-shifted versions always inherit their source split.
- Checkpoints are selected with validation only.
- The final evaluator loads only the locked test partition and uses fixed,
  equal averaging across seeds and test-time views.
- Test labels are not used for calibration, thresholding, class weighting,
  checkpoint selection, or ensemble-weight selection.

## Before running

1. Keep the project folder as `FSC22_Research`.
2. Activate the existing environment:

   ```bat
   conda activate fsc22_research
   ```

3. Confirm these existing caches are present:

   - `outputs\ast_cache` with 2,025 files
   - `outputs\ast_pitch_cache` with 4,050 files

   The earlier preparation already created them. If either cache is missing,
   run `prepare_ast_features.py` and then `prepare_paper_protocol.py` once.

## Run

Double-click or execute:

```bat
run_clean_unseen_training.bat
```

The batch file performs the following operations in order:

1. Creates a nested `StratifiedGroupKFold` split.
2. Trains seed 101 using train and validation only.
3. Trains seed 202 using train and validation only.
4. Trains seed 303 using train and validation only.
5. Evaluates the untouched test partition once using a probability ensemble
   and unseen-clip test-time augmentation.

The final results are written to:

```text
outputs\clean_ast_v1_locked_test
```

Upload that complete folder as a ZIP for independent metric verification.

## GPU note

The supplied command unfreezes eight AST transformer blocks. It should fit a
4 GB RTX 3050 with batch size four. If CUDA reports an out-of-memory error,
change `--unfrozen-blocks 8` to `--unfrozen-blocks 6` for all three seeds and
restart with a new tag such as `clean_ast_v1_6block` so partial runs are not
mixed.

## Scientific interpretation

The earlier 98.27% score must remain labelled as a transductive source-overlap
analysis. Only the metrics generated by `evaluate_clean_ast_ensemble.py` are
eligible to be described as clean unseen-recording performance. A score of 98%
cannot be guaranteed in advance; it is established only if the locked evaluator
produces it without altering the protocol after inspecting test results.
